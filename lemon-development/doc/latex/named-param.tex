\hypertarget{named-param_named-func-param}{}\doxysection{Named Function Parameters}\label{named-param_named-func-param}
Several modern languages provide a convenient way to refer the function parameters by name also when you call the function. It is especially comfortable in case of a function having tons of parameters with natural default values. Sadly, C++ lacks this amenity.

However, with a crafty trick and with some little inconvenience, it is possible to emulate is. The example below shows how to do it.


\begin{DoxyCode}{0}
\DoxyCodeLine{\textcolor{keyword}{class }namedFn}
\DoxyCodeLine{\{}
\DoxyCodeLine{  \textcolor{keywordtype}{int} \_id;}
\DoxyCodeLine{  \textcolor{keywordtype}{double} \_val;}
\DoxyCodeLine{  \textcolor{keywordtype}{int} \_dim;}
\DoxyCodeLine{}
\DoxyCodeLine{  \textcolor{keyword}{public}:}
\DoxyCodeLine{  namedFn() : \_id(0), \_val(1), \_dim(2) \{\}}
\DoxyCodeLine{  namedFn\& id(\textcolor{keywordtype}{int} p)     \{ \_id  = p ; \textcolor{keywordflow}{return} *\textcolor{keyword}{this}; \}}
\DoxyCodeLine{  namedFn\& val(\textcolor{keywordtype}{double} p) \{ \_val = p ; \textcolor{keywordflow}{return} *\textcolor{keyword}{this}; \}}
\DoxyCodeLine{  namedFn\& dim(\textcolor{keywordtype}{int} p)    \{ \_dim = p ; \textcolor{keywordflow}{return} *\textcolor{keyword}{this}; \}}
\DoxyCodeLine{}
\DoxyCodeLine{  run() \{}
\DoxyCodeLine{    std::cout << \textcolor{stringliteral}{"{}Here comes the function itself\(\backslash\)n"{}} <<}
\DoxyCodeLine{              << \textcolor{stringliteral}{"{}With parameters "{}}}
\DoxyCodeLine{              << \_id << \textcolor{stringliteral}{"{}, "{}} << \_val << \textcolor{stringliteral}{"{}, "{}} << \_dim << std::endl;}
\DoxyCodeLine{  \}}
\DoxyCodeLine{\};}

\end{DoxyCode}


Then you can use it like this.


\begin{DoxyCode}{0}
\DoxyCodeLine{namedFn().id(3).val(2).run();}

\end{DoxyCode}


The trick is obvious, each \char`\"{}named parameter\char`\"{} changes one component of the underlying class, then gives back a reference to it. Finally, {\ttfamily run()} executes the algorithm itself.

\begin{DoxyNote}{Note}
Although it is a class, named\+Fn is used pretty much like as it were a function. That it why we called it named\+Fn instead of {\ttfamily Named\+Fn}.

In fact, the final {\ttfamily .run()} could be made unnecessary, because the algorithm could also be implemented in the destructor of {\ttfamily named\+Fn} instead. This however would make it impossible to implement functions with return values, and would also cause serious problems when implementing \mbox{\hyperlink{named-param_named-templ-func-param}{named template parameters}}. {\bfseries{Therefore, by convention, {\ttfamily .run()} must be used explicitly to execute a function having named parameters everywhere in LEMON.}}
\end{DoxyNote}
\hypertarget{named-param_named-templ-func-param}{}\doxysection{Named Function Template Parameters}\label{named-param_named-templ-func-param}
A named parameter can also be a template function. The usage is exactly the same, but the implementation behind is a kind of black magic and they are the dirtiest part of the LEMON code.

You will probably never need to know how it works, but if you really committed, have a look at lemon/graph\+\_\+to\+\_\+eps.\+h for an example.\hypertarget{named-param_traits-classes}{}\doxysection{Traits Classes}\label{named-param_traits-classes}
A similar game can also be played when defining classes. In this case the type of the class attributes can be changed. Initially we have to define a special class called {\itshape Traits Class} defining the default type of the attributes. Then the types of these attributes can be changed in the same way as described in the next section.

See lemon\+::\+Dijkstra\+Default\+Traits for an example how a traits class implementation looks like.\hypertarget{named-param_named-templ-param}{}\doxysection{Named Class Template Parameters}\label{named-param_named-templ-param}
If we would like to change the type of an attribute in a class that was instantiated by using a traits class as a template parameter, and the class contains named parameters, we do not have to instantiate again the class with new traits class, but instead adaptor classes can be used as shown in the following example.


\begin{DoxyCode}{0}
\DoxyCodeLine{Dijkstra<>::SetPredMap<NullMap<Node,Arc> >::Create}

\end{DoxyCode}


It can also be used in conjunction with other named template parameters in arbitrary order.


\begin{DoxyCode}{0}
\DoxyCodeLine{Dijkstra<>::SetDistMap<MyMap>::SetPredMap<NullMap<Node,Arc> >::Create}

\end{DoxyCode}


The result will be an instantiated Dijkstra class, in which the Dist\+Map and the Pred\+Map is modified.
